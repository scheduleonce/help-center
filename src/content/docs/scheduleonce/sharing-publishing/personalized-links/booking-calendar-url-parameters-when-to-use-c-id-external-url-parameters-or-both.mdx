Avoid asking your guests for information you already have.

Use the `c_id` parameter to identify an existing OnceHub Contact, external URL parameters to prefill contact information and other booking form questions from an outside source, or both together when you are not sure whether a Contact is in OnceHub.

---

## Which Approach Fits You Best?

### Your guests' contact details are all stored in OnceHub

**Use `c_id` on its own:** The link carries an identifier, allowing OnceHub to retrieve the Contact's stored details without displaying those details in the URL or to the guest. OnceHub skips questions mapped to Contact Properties that already have saved values and asks only for required information that is missing. If all required information is available, the guest does not see the booking form.

Use the Contact ID when possible. If you use a stored email address as the `c_id` value, that email address is visible in the URL.

For details, see [Option 1: The `c_id` (Contact ID) Parameter](#option-1-the-c_id-contact-id-parameter). For example, send a personalized link to an existing Contact:

`https://oncehub.com/example?c_id=CTC-xxxxxxxxxxxxxx`

### Your guests' contact details are not in OnceHub

**Use external URL parameters on their own:** The link carries the details themselves, so they are visible in the URL. They appear prefilled for the guest to review. Add `skip=1` to skip the form when all required information is provided.

For details, see [Option 2: External URL Parameters](#option-2-external-url-parameters). For example, prefill guest details from an external CRM and skip the form:

`https://oncehub.com/example?name=John%20Doe&email=john.doe@example.com&skip=1`

### You're not sure where your guests' contact details live

**Use both in the same link:** One link can work for guests with and without an existing OnceHub Contact. OnceHub uses `c_id` to identify a matching Contact and skips questions it already has answers for. External URL parameters can prefill the remaining questions and provide details for guests who do not have a matching Contact.

For details, see [Option 3: Using `c_id` and External URL Parameters Together](#option-3-using-c_id-and-external-url-parameters-together). For example, use CRM placeholders in an email broadcast:

`https://oncehub.com/example?c_id={contact_email}&name={contact_name}&email={contact_email}`

When an email address is used as the `c_id` value, it is visible in the URL.

---

## How Skipping Works

The two approaches skip booking form content differently:

- **When using `c_id` (question-level skipping):** OnceHub skips each booking form question mapped to a Contact Property that already has a saved value. This happens automatically. If all required questions are skipped, the entire booking form is skipped automatically.
- **When using external URL parameters:** The `skip=1` parameter explicitly instructs OnceHub to skip the booking form step. It takes effect only when all mandatory questions are prefilled through the URL. Without `skip=1`, the booking form is displayed even if all the data is provided.

<Aside type="note">
  If the SMS number question on your booking form is prefilled, the booking form
  can still be skipped automatically. Because the guest does not interact with
  the booking form, SMS opt-in consent is not collected and remains false.
</Aside>

## Option 1: The `c_id` (Contact ID) Parameter

The `c_id` parameter uses either a unique Contact ID (for example, `c_id=CTC-xxxxxxxxxxxxxx`) or the email address stored on an existing Contact (for example, `c_id=john@example.com`) to associate the booking with that Contact.

### Prerequisites

For OnceHub to skip booking form questions for an existing Contact:

- Your booking form questions must be mapped to the corresponding Contact Properties.
- The mapped Contact Properties must contain values in the Contact record.

### When to Use

Use `c_id` when scheduling with existing OnceHub Contacts, such as when sending a personalized booking link manually or in an email campaign. Guests can book without re-entering information you already hold.

### How It Works

Append a Contact ID or stored email address to your booking link. Use the Contact ID when possible; if you use an email address, it will be visible in the URL.

`https://oncehub.com/example?c_id=CTC-xxxxxxxxxxxxxx`

`https://oncehub.com/example?c_id=john@example.com`

OnceHub matches the `c_id` value to the existing Contact and skips questions for which your organization already has answers.

If all required mapped questions have values, OnceHub automatically skips the booking form. If any required information is missing, only those questions are displayed. You do not need to add `skip=1` when you use `c_id`.

**Data privacy:** The Contact's stored property values are not exposed in the URL or displayed to the guest. However, if you use an email address as the `c_id` value, that address itself is visible in the URL. Using the Contact ID is the more private option.

## Option 2: External URL Parameters

External URL parameters pass field values directly in the booking link. The values are visible in the browser address bar and are used to prefill the corresponding booking form fields.

### When to Use

Use external URL parameters when:

- **Scheduling with new Contacts or capturing details live:** You are collecting information from a guest who does not have a Contact record in OnceHub, such as during a phone call, live chat, or an email campaign sent from an external CRM.
- **Sending outbound campaigns to external leads:** You are sending promotional emails or booking invitations from an external marketing tool or CRM to new prospects whose records do not exist in OnceHub, and dynamically populating their details using URL merge tags.
- **Allowing guests to verify information:** You want guests to review or edit their details before finalizing the booking. This is the default when you do not use `skip=1`.
- **Passing data from external systems:** Guest information is stored in a third-party form, application, or CRM.

### How It Works

Append the relevant parameter keys and values to your booking link:

| Question / Field  | URL Syntax      | Description                               | Example                       |
| :---------------- | :-------------- | :---------------------------------------- | :---------------------------- |
| Contact Full Name | `name=`         | Prefills the guest's full name.           | `name=John%20Doe`             |
| Contact Email     | `email=`        | Prefills the guest's email address.       | `email=john.doe@example.com`  |
| SMS Number        | `mobile_phone=` | Prefills the guest's mobile phone number. | `mobile_phone=%2B17793129776` |

You can also prefill custom questions. Each question has its own URL parameter, which you can find using **Personalization and Tracking** in the **Share** popup of your Booking Calendar.

### Specific Parameter Processing Rules

- **Phone numbers:** Encode the `+` as `%2B`, followed immediately by the country code and the rest of the number, without spaces or dashes. For example, use `mobile_phone=%2B17793129776` for +1-779-312-9776.
- **Invalid values:** If a value is in an invalid or incorrect format, the question is displayed to the guest.

For example:

`https://oncehub.com/example?name=John%20Doe&email=john.doe@example.com`

The values are visible in the browser address bar. By default, prefilled questions remain visible so guests can review or edit them. If any required question is empty, the guest must answer it before booking.

### Skipping the Booking Form

To skip the booking form, append `&skip=1`. This skips the entire booking form step only when all mandatory questions are prefilled through URL parameters. Without it, the form is shown even when all the data is provided.

`https://oncehub.com/example?name=John%20Doe&email=john.doe@example.com&skip=1`

If any required fields remain empty, OnceHub displays those fields before the booking can be completed.

## Option 3: Using `c_id` and External URL Parameters Together

Using `c_id` and external URL parameters in the same link lets OnceHub recognize guests who have a Contact record, while the external URL parameter values cover guests who do not have a Contact in OnceHub. OnceHub skips the questions it already has answers for, and the external URL parameter values prefill the rest. The two types of URL parameters complement each other.

### When to Use

Use both when:

- **You are not sure where your guests' details are stored:** Some invitees have Contact records in OnceHub and some do not.
- **Your audience is a mix and you want one link for everyone:** For example, you are inviting CRM contacts, leads, and clients to the same webinar.

### Prerequisites

For guests who have a Contact record, your booking form questions must be mapped to Contact Properties, and those properties must contain values in the Contact record.

### How It Works

Add the Contact ID or stored email address, together with the external URL parameters, to the same booking link:

`https://oncehub.com/example?c_id=CTC-xxxxxxxxxxxxxx&name=John%20Doe&email=john.doe@example.com`

OnceHub skips the questions it already has answers for through `c_id`. The values in the link prefill the rest.

## Example: Webinar Invitation

A financial advisory firm invites its contacts to a webinar called “Fixed income opportunities for your retirement.” The booking form asks for a name, an email, and three qualifying questions: Primary Financial Goal, Retirement Timeline, and Investible Portfolio. Each question is mapped to a Contact Property.

The firm sends the same link to everyone, using the recipient's email address as the `c_id` value:

`https://oncehub.com/example?c_id={contact_email}&name={contact_name}&email={contact_email}`

The values in curly braces are placeholders. The email or marketing tool replaces them with each recipient's details when it sends the invitation. For John Doe, the link becomes:

`https://oncehub.com/example?c_id=john.doe@example.com&name=John%20Doe&email=john.doe@example.com`

The same link serves three types of invitee:

| Invitee                                                                       | What happens                                                                                                                              | What the guest sees                                                                        |
| :---------------------------------------------------------------------------- | :---------------------------------------------------------------------------------------------------------------------------------------- | :----------------------------------------------------------------------------------------- |
| **In your CRM but not in OnceHub**                                            | There is no matching Contact, so the name and email in the link prefill the form.                                                         | The form with the name and email filled in, plus all three qualifying questions to answer. |
| **A lead in OnceHub**                                                         | `c_id` identifies the Contact, and OnceHub skips the name and email questions. The lead has no saved answers to the qualifying questions. | Only the three qualifying questions.                                                       |
| **A Prospect, Onboarding Client, Active Client, or Former Client in OnceHub** | `c_id` identifies the Contact, and OnceHub already has every answer.                                                                      | No booking form. The webinar place is reserved.                                            |

**Note:** Because this link carries the name and email as values, they are visible in the URL.
