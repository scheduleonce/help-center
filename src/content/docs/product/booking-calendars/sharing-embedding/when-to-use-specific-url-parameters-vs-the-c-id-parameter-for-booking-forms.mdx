Avoiding redundant booking form questions by not asking for information that is already available in your organization simplifies the scheduling process for your guests.

To choose the right approach for your workflow, start by identifying where your guest data resides:

- **In OnceHub Contact Records:** Use the `c_id` (Contact ID) parameter to associate the booking with an existing Contact and securely retrieve stored information.
- **Outside OnceHub or is captured live:** Use external URL parameters to pass field values directly through the booking link.

---

## Option 1: The `c_id` (Contact ID) Parameter

The `c_id` parameter uses either a unique Contact ID (for example, `c_id=CTC-12345`) or the email address stored on an existing Contact (for example, `c_id=john@example.com`) to associate the booking with that Contact.

### Prerequisites

For OnceHub to automatically answer booking form questions on the backend:

1. Your booking form questions must be mapped to the corresponding Contact Properties.
2. The mapped Contact Properties must contain values in the Contact record.

### When to Use

Use the `c_id` parameter when:

- **Scheduling with existing OnceHub Contacts:** Share a personalized booking link manually or via CRM/email campaigns using the Contact ID or stored email address to provide an instant, seamless booking experience without requiring guests to re-enter their information.

### How It Works

Append a Contact ID or stored email address to your booking link:

- `https://oncehub.com/example?c_id=CTC-12345`
- `https://oncehub.com/example?c_id=john@example.com`

OnceHub matches the `c_id` value to the existing Contact and uses the stored information to avoid asking questions for which your organization already has the information.

If all required mapped questions have values, OnceHub automatically skips the booking form. If any required information is missing, only those questions are displayed.

**Data privacy safeguard**: Contact information stored in OnceHub is not exposed in the URL or displayed to the guest.

---

## Option 2: External URL Parameters

External URL parameters pass field values directly in the booking link. The values are visible in the browser address bar and are used to prefill the corresponding booking form fields.

### When to Use

Use external URL parameters when:

- **Scheduling with new Contacts or capturing details live:** You are collecting information from a guest who does not have an existing contact record in OnceHub, such as during a phone interaction or live chat interaction, and want to prefill their details into the URL link.
- **Allowing guests to verify information:** You want guests to review or edit their details before finalizing the booking.
- **Passing data from external systems:** Guest information resides in a third-party form, application, or integrated CRM.

### How It Works

Append the relevant parameter keys and values to the booking link:

- `https://oncehub.com/example?name=John%20Doe&email=john@example.com`

The values are used to prefill the corresponding booking form fields.

By default, the fields remain visible so guests can review or edit the information. To skip the booking form, append `&skip=1`.

- `https://oncehub.com/example?name=John%20Doe&email=john@example.com&skip=1`

If any required fields remain empty, OnceHub displays those fields before the booking can be completed.

---

## Feature Comparison Summary

The table below compares key differences in data privacy, visibility, and form behavior between the `c_id` parameter and the external URL parameters.

| Feature / Scenario         | `c_id` Parameter                                                                         | External URL Parameters                               |
| :------------------------- | :--------------------------------------------------------------------------------------- | :---------------------------------------------------- |
| **Best Suited for**        | Existing OnceHub Contacts                                                                | New Contacts or data from external integrations       |
| **Data Passed in the URL** | Contact ID or stored email address                                                       | Actual field values such as name or email             |
| **Data Visibility**        | Stored Contact properties are not exposed; an email used as `c_id` is visible in the URL | Values are visible in the URL and in prefilled fields |
| **Form Skipping**          | Automatic when all required mapped Contact Properties contain values                     | Optional with `&skip=1`                               |
| **Guest Editing**          | Guests only provide missing required fields                                              | Guests can review and edit prefilled information      |
